# Connecting Blender to this project

Written because the question keeps recurring and the answer has a hard
constraint in it that is easy to miss.

## The constraint

**A remote agent session cannot reach your Blender.** The agent working in this
repo through claude.ai/code runs in a container in a datacentre; Blender runs on
your desk. Every Blender bridge that exists works over a **localhost socket**
between a Blender add-on and an MCP server on the *same machine*. There is no
version of that which crosses into a remote sandbox, and making one would mean
punching through the network isolation the sandbox exists to provide.

So "connect Claude to Blender" resolves to one of three different things, and
they are not interchangeable.

## The three options

| | What runs where | What it can do | What it costs |
|---|---|---|---|
| **1. The contract add-on** *(in the repo, working)* | `tools/blender/studio137.py` inside your Blender | Checks your scene against the asset contract and exports correctly. No AI involved. | Nothing. Already built and tested. |
| **2. `blender-mcp` + local Claude** | A Blender add-on plus an MCP server, both on **your machine**, driven by Claude Desktop or a local Claude Code | An agent that can see your scene and write Python into it — create and modify objects, materials, lighting, run arbitrary Python | A local setup, and a real caveat below |
| **3. This remote session** | Container, no Blender GUI. Has `bpy` 4.5 LTS as a Python module | Generates and inspects `.glb` headlessly; validates your exports; cannot see or touch your Blender | Already working. `tools/blender/console_proxy.py` is the proof. |

These compose. 1 and 3 are already in place and cover the whole asset pipeline.
2 adds an agent *inside* Blender, which is a genuinely different capability —
it is the only one that can model for you.

### The caveat on option 2

`blender-mcp` works by **executing arbitrary Python inside Blender**. That is
what makes it powerful and it is also the whole risk: an agent that can run any
Python in your session can delete your scene, and Blender's undo does not
reliably cover script-driven changes. If you set it up:

- Save before you let it touch anything, and work in a copy of the `.blend`.
- Keep the hero console file out of its reach until you trust it.

It supports Blender 3.0+ per its own documentation. **5.x is not explicitly
confirmed** in that documentation — treat 5.2 as untested rather than supported,
and have 4.5 LTS available as a fallback if the add-on refuses to register.

## What a session setting up option 2 needs to know about this repo

The thing a fresh local agent will *not* know, and will otherwise rediscover the
hard way:

1. **The console is a named-parts contract, not a free-form model.** It is
   specified in `docs/console-asset-contract.md` and enforced three times:
   `tools/blender/studio137.py` (in Blender), `tools/asset-forge/validate-console.mjs`
   (on the exported file), and `src/components/studio/Props.tsx` (at runtime,
   which is the one that wins if they ever disagree).
2. **The names are an API.** `Body_Iron`, `Trim_Brass`, `CRT_Bezel`, `CRT_Glass`,
   `CRT_Display`, `Panel_Controls`, `Knob_NN`, `Collision_Console`,
   `FocusAnchor`, all under `ConsoleRoot`. Four materials: `M_Iron`, `M_Brass`,
   `M_Glass`, `M_Display`. Blender's `.001` duplicate suffixes are handled — do
   not hand-rename copies.
3. **There is already a working blockout** at `public/models/consoleMV-proxy.glb`,
   generated by `tools/blender/console_proxy.py`. Do not start from a cube; start
   from that, or from the script that makes it.
4. **Do not build a second validator.** Run the panel.
5. **No lever machine.** A 4-bit lever navigation model was proposed and
   declined; the doors in this room are objects. `Lever_N` nodes mean somebody is
   working from the wrong document.

## The loop that works today, with no bridge at all

1. Model in Blender. Press **Check contract** in the 137 sidebar until clean.
2. **Export consoleMV.glb** → `public/models/consoleMV.glb`.
3. Commit and push.
4. `node tools/asset-forge/validate-console.mjs public/models/consoleMV.glb`
   confirms it independently, and the room picks it up with no code change.

Option 2 changes step 1 and nothing else.
